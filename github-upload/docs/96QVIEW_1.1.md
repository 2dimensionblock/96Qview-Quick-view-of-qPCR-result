# 96Qview 1.1 使用说明

## 样本命名

支持 `基因-时间` 和 `基因-组别-时间`，例如 `GAPDH-24`、`GeneX-Control-24`；下划线也可用作分隔符。基因名称需含字母或汉字。基因、组别和横轴值如果已经放在独立列中，以独立列为准。

内参识别覆盖：GAPDH、ACTB、18S rRNA、28S rRNA、B2M、HPRT1、TBP、PPIA、UBC、SDHA、RPL13A、RPLP0、YWHAZ、PGK1、HMBS、GUSB、ALAS1、ACT7、ACT11、ACT2、TUB、EF1a、UBQ10、UBQ9、PP2A、SAND、16S rRNA、rpoB、gyrB、recA、ACT1、PDA1、TEF1、RDN18。不区分大小写，同一种内参的大小写写法会合并。检测到多个候选内参时，默认选择首次出现者，可在“内参基因”中调整。

数字按样本名称中的位置判断，并统计当前工作表该位置的最大值；Ct、孔号和独立列不参与这个判断。若存在最大值大于 8 的命名位置，忽略其他最大值不超过 8 的纯数字位置；若不存在，则保留所有数字位置。带常用时间、浓度或温度单位的数字也按数字值判断。

| 样本名称集合 | 结果 |
| --- | --- |
| GeneX-0、GeneX-4、GeneX-8 | 全部保留为横轴值 |
| GeneX-0、GeneX-4、GeneX-8、GeneX-24 | 同一位置最大值为 24，因此 0、4、8、24 全部保留 |
| GeneX-1-0、GeneX-2-4、GeneX-3-24 | 第一个数字位置最大值为 3，忽略；横轴保留 0、4、24 |
| GeneX-1-0、GeneX-2-4 | 没有位置最大值大于 8，组别 1、2 与横轴 0、4 都保留 |
| GeneX-Control-0、GeneX-Control-24 | 文本组别 Control 与横轴 0、24 都保留 |

只有所有导入记录的基因都为“待指定”时，才自动弹出命名识别失败提示。提示区分未映射列、纯数字/空样本名与占位名称等情况，并提供列映射和孔自定义入口。少数未识别的基因可在“分组校对”中修改。

## 内参被标为阴性对照时

若文件可读入且 Ct 有效，但“可计算的目标孔”为 0，请查看结果上方的检测类型冲突提示。部分仪器导出文件可能把内参孔标为“阴性对照 / Negative”，这些孔默认不参与归一化。

确认这些孔实际为内参样本后，点击“将这 … 孔用作内参”，程序即重新计算。点击“恢复按阴性对照排除”可撤销；重新导入文件也会重置。原始表格不变，导出结果会记录这次解释调整。明确标注 NTC、无模板或空白对照的孔不通过此按钮纳入。

## 孔自定义

1. 先导入带 Ct/Cq 的数据，再点击“孔自定义”。
2. 窗口包含 A–H × 1–12 的 96 个正方形孔位。孔号支持 A1–H12、A01 等写法，以及按行排列的 1–96。
3. 左侧 8 栏为行命名，上侧 12 栏为列命名。一个方向为基因，另一个方向为组别；更改任一方向会自动切换另一方向，不能同时选择同一类型。切换方向会清空批量输入框，保留已有孔数据及单孔覆盖。
4. 选择组别类型：时间、浓度、温度或自定义，并填写单位。组别可为数值或文本。
5. 双击孔位，或聚焦后按 Enter，编辑该孔基因、组别值、类型和单位；点击“保存该孔”。单孔命名优先于行列批量命名，“恢复行列命名”可移除覆盖。
6. “确认命名”将有数据的孔按自定义基因和组别重新分析。空孔不产生 Ct 数据；原始样本名、Ct、重复编号和排除状态均保留。取消窗口则放弃本次修改。

新组别用作横轴，内参与目标按相同组别值和生物重复匹配。已有的“组别 + 时间”组合会预填为组合文本。多板重复孔号、96 孔范围外孔号、同孔含目标与内参的配对宽表需要先拆分成单块板、每孔一行的数据。

## 绘图与作者链接

“图形类型”可选折线图、柱形图、柱形与折线叠加图。三种模式均支持 SD/SEM 误差棒、线性/对数纵轴、图例筛选、SVG/PNG 导出。柱形按系列并排排列，叠加折线通过各柱均值位置；n < 2 时不绘制误差棒。对数柱形从最小正刻度绘制，非正误差端点截断并提示。

计算方法保持原有 ΔCt、ΔΔCt 和平均 2^−ΔCt；图形类型不改变统计结果。

应用名称为 **96Qview**，移除了界面底部署名。桌面菜单栏和页面顶栏均有“关于作者”，可访问 GitHub 账号 **2dimensionblock** 及用户指定的[发布项目页](https://github.com/2dimensionblock/qPCR-studio-Quick-view-of-qPCR-result)。点击后在系统默认浏览器打开；数据分析仍在本机完成。

## 开发

新增 `frontend/naming.cjs`、`frontend/import.js`、`frontend/plate.js`、`frontend/chart.js` 和样式文件作为可维护源码。`frontend/legacy.html` 保存原版依赖、字体和未改动的功能；构建脚本校验每个替换锚点后生成自包含 `app/index.html`，不需要运行时网络依赖。原版完整 React/TypeScript 工程仍未恢复。

执行 `npm run build:frontend`、`npm test`、`npm run check`；`npm run dist:win` 会自动重新生成前端。运行 `npm run verify:dist` 校验实际便携 EXE，`npm run smoke:windows` 验证实际 Windows 窗口和导出，再运行 `npm run release:files` 整理发布文件。
